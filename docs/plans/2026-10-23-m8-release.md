# M8 — Build + Pre-release + Playtest Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Friends download a zip from GitHub Releases, unzip it and join the user's room from another network.

**Architecture:** `build-windows.ps1 -Zip` makes the zip with a Thai/English `README.txt` inside it. `verify-zip.ps1` unzips it to a temp folder and runs the smoke test from there. `check-secrets.ps1` scans the tracked files and the whole git history before the repo goes public. `release.ps1` chains these checks and then runs `gh release create`, with a `-DryRun` mode that does everything except publish. Docs are `README.md` and `docs/PLAYTEST_CHECKLIST.md`.

**Tech Stack:** PowerShell 5.1, git, GitHub CLI 2.103.0, Unity 6000.6.7f1 batchmode.

**Spec:** `docs/PLAN.md` (M8), `docs/GDD.md`.

## Global Constraints
- Tag `v0.1.0-alpha`, published as a pre-release. `GameVersion.Current` stays `"0.1.0"`, because the handshake compares it exactly.
- Zip name: `BOO-TRAYAL-v0.1.0-win64.zip`. Never commit zips; they are uploaded to Releases only.
- Never commit secrets, API keys or service-account files. Secrets must be scanned for before the repo turns public.
- Repo `LumielX/GameByClaude` turns Public only after the user confirms in chat.
- Keep Thai files UTF-8. Never write them with PowerShell 5.1 `Set-Content`/`Get-Content`; .ps1 scripts read text with `-Encoding UTF8`.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus
1. **Pre-release download link.** `/releases/latest` ignores pre-releases, so the in-game "download latest" link 404s. Expected: the link opens `/releases`. Owner: Task 1 (test on `NetMessages.ReleasesUrl`).
2. **Running from the unzipped folder.** The zip must run from any folder, including a path with Thai characters and spaces. Expected: the smoke test passes. Owner: Task 1 (`verify-zip.ps1` extracts into `...\ทดสอบ BOO\`).
3. **Unsafe release state.** `release.ps1` run with a dirty tree, an unpushed main or an existing tag must refuse before building. Owner: Task 3 (dry-run checks).
4. **Secrets anywhere in history.** A secret deleted in a later commit is still public once the repo goes Public. Expected: the scan covers all commits. Owner: Task 2 (self-test with a planted fake key in a temp repo).
5. **Windows SmartScreen and the firewall prompt.** These scare friends into giving up. Expected: README and README.txt explain "More info → Run anyway" and allowing the firewall. Owner: Task 4.

### Task 2: Secret scan (tracked files + full history)

**Files:**
- Create: `tools/check-secrets.ps1` (params `[string]$Repo = <project root>`, `[switch]$SelfTest`)

**Interfaces:**
- Produces: exit 0 and `SECRETS OK commits=<n>`, or exit 1 with `SECRET <commit|HEAD> <path>: <pattern name>` per hit (the value itself is never printed). Task 3 calls it.

- [ ] Patterns:
  - private key blocks: `-----BEGIN [A-Z ]*PRIVATE KEY-----`
  - AWS keys: `AKIA[0-9A-Z]{16}`
  - GitHub tokens: `gh[pousr]_[A-Za-z0-9]{36}`
  - Google API keys: `AIza[0-9A-Za-z_-]{35}`
  - a non-empty Vivox `"tokenKey"\s*:\s*"[^"]+"`
  - a service-account JSON `"type"\s*:\s*"service_account"`
  - `client_secret`
  - file names `*.pem`, `*.p12`, `*.pfx`, `*serviceaccount*.json`, `*credentials*.json`, `.env`
- [ ] History: run `git log --all -p --no-color -G<combined regex>` to find the commits, then report the commit and path. Tracked files: `git grep -nIE`.
- [ ] `-SelfTest`:
  - Create a temp repo.
  - Commit a file holding a fake `AKIA` key plus 16 letters, then delete the file in a second commit.
  - Run the scan against it and require exit 1 with the first commit's hash.
  - Run it against a clean temp repo and require exit 0.
- [ ] Run `check-secrets.ps1 -SelfTest`, then `check-secrets.ps1`. Expected: `SELFTEST OK`, then `SECRETS OK` (or real hits, which must be stopped and reported to the user).
- [ ] Commit `feat(release): secret scan over tracked files and full history`.

### Task 3: release.ps1

**Files:**
- Create: `tools/release.ps1` (params `[string]$Tag = "v$((GameVersion))-alpha"` from `GameVersion.cs`, `[switch]$DryRun`, `[switch]$SkipBuild`, `[switch]$MakePublic`)
- Create: `docs/release/notes-v0.1.0-alpha.md` (Thai first, then English: what's in it, how to install, known issues, how to report)

**Interfaces:**
- Consumes: `build-windows.ps1 -Zip`, `verify-zip.ps1 -Zip <path>`, `check-secrets.ps1`.

- [ ] Preconditions, in this order, each exiting 1 with a plain message:
  1. `gh` exists and `gh auth status` succeeds (skipped in `-DryRun`, with a warning).
  2. The branch is `main`.
  3. `git status --porcelain` is empty.
  4. `git fetch origin` succeeds and `HEAD == origin/main`.
  5. The tag does not exist locally or on the remote (`git ls-remote --tags origin $Tag`).
  6. The notes file `docs/release/notes-$Tag.md` exists.
  7. `check-secrets.ps1` passes.
- [ ] Unless `-SkipBuild`, run `run-tests.ps1` and `build-windows.ps1 -Zip`. Always run `verify-zip.ps1`.
- [ ] If `-MakePublic`, run `gh repo edit LumielX/GameByClaude --visibility public --accept-visibility-change-consequences`. The script never does this on its own.
- [ ] Publish:
  - Normal run: `gh release create $Tag <zip> --prerelease --target main --title "BOO-TRAYAL $Tag" --notes-file <notes>`, then print the release URL from `gh release view $Tag --json url`.
  - `-DryRun`: print the exact command and `RELEASE DRY RUN OK`.
- [ ] Check: make a scratch edit to `README.md` (dirty tree), run `release.ps1 -DryRun -SkipBuild`. Expected: refuses with "uncommitted changes". Revert.
- [ ] Commit, push, then run `release.ps1 -DryRun`. Expected: tests, build, `ZIP OK`, `SECRETS OK`, `RELEASE DRY RUN OK`.
- [ ] Commit `feat(release): release script with dry run`.
