# M3: Player Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A networked first-person player can walk, run (stamina + adrenaline multipliers), jump, crouch, look and toggle a flashlight. Players can pick up and throw light items, carry a heavy item together (drag it alone, slowly and noisily), and push friends, who stumble and get knocked down. Dropped items make noise events for the ghost (M4). All of this works between two built instances.

**Architecture:**
- Movement, carry, push, knockdown and noise numbers are pure Core rules (TDD).
- `PlayerMotor` (Game) applies them through a `CharacterController`, with owner-authoritative `NetworkTransform` and interpolation.
- Input comes through `IPlayerInput`, with two implementations: Input System actions built in code (`PlayerInputReader`), or a scripted `BotInput` that the smoke test uses.
- Items are `GrabbableItem`s:
  - Light items: ownership moves to the holder, who moves them.
  - Heavy items: stay server-authoritative. The server moves them toward the holders' hold points, and needs 2 holders to lift (1 holder drags).
- A `SessionFlow` component loads `Sandbox` when hosting starts and goes back to `Menu` when offline.
- A test-only `SmokeProbe` (`-smokeprobe` flag) scripts bots and logs markers for `tools/unity/player-smoke.ps1`.

**Tech Stack:** NGO 2.13.3 (`NetworkTransform` AuthorityMode.Owner, `NetworkRigidbody`, `[Rpc(SendTo.Server/Owner)]`, `NetworkVariable` with owner write), Input System 1.20.1, URP.

**Spec:** `docs/GDD.md` §5 (player, controls, carry, knockdown) and §6.3 (adrenaline); `docs/PLAN.md` M3.

## Global Constraints
- All earlier constraints still apply.
- Controls (GDD §5):
  - WASD move, Shift run, Space jump, Ctrl/C crouch, mouse look
  - E grab/interact, LMB throw held item, G drop, RMB push
  - F flashlight, Esc frees the cursor (debug menu usable)
- Movement numbers are my calls and live as constants in Core:
  - walk 3.2, run 5.6, crouch 1.6 m/s
  - jump 4.8 m/s, gravity −18 m/s²
  - light carry ×0.9, heavy shared ×0.65, heavy alone (drag) ×0.35
  - no jumping while carrying heavy or knocked down
- Push: range 2.5 m, cooldown 1.0 s, knockback 4.5 m/s. Knockdown 1.5 s when the pusher moves at ≥ 80% of run speed.
- Grab range 2.2 m. Heavy items take max 2 holders, light items 1.
- Noise from impacts: impulse < 2 → none. Loudness = clamp01((impulse − 2) / 10), doubled for heavy items. Radius = 4 + 16 × loudness m. Running footsteps: loudness 0.25 (radius 8). Walking and crouching: silent.

## Review Focus
1. **Two players grab the same light item in the same frame:** only one gets it. → server-side check (`CarryRules.CanGrab`) + smoke step.
2. **The holder disconnects while holding:** the item drops and returns to server authority, and does not hang mid-air forever. → `GrabbableItem` handles `OnClientDisconnect` (smoke: kill client while holding → server logs `ITEM_RELEASED reason=disconnect`).
3. **Pushing while knocked down, or pushing yourself:** refused. → `PushRules` tests.
4. **A late joiner** gets placed at a spawn point and sees held items in the right place. → smoke joins the client after the host loaded Sandbox.
5. **Throwing at a huge velocity, or NaN input from a bot:** clamped. → `MovementModel`/`CarryRules.ClampThrow` tests.

### Task 4: Items, hands, push, SessionFlow, Sandbox scene
**Files:**
- `Game/Items/GrabbableItem.cs`, `Game/Items/NoiseBus.cs`
- `Game/Player/PlayerHands.cs`, `Game/Player/PlayerPush.cs`
- `Game/Flow/SessionFlow.cs`
- `Editor/Builders/SandboxBuilder.cs`, `Editor/Builders/ItemPrefabBuilder.cs`
- `SceneBuilder` adds a `Menu` scene; build settings become [Bootstrap, Menu, Sandbox]

**Interfaces:**
- `NoiseBus` (server only): `static event Action<Vector3, Noise> Raised`, `static void Raise(Vector3 pos, Noise n)`. Raise logs `NOISE loud=<0.00> r=<m>`.
- `GrabbableItem : NetworkBehaviour`:
  - Fields: `[SerializeField] bool heavy`, `string ItemId`
  - `NetworkList<ulong> Holders`
  - `bool TryGrab(ulong clientId, Vector3 holdPoint)` (server)
  - `void Release(ulong clientId, Vector3 throwVelocity)` (server)
  - Light item:
    - Grab: `ChangeOwnership(holder)`; the holder keeps it kinematic at its HoldPoint.
    - Release: `RemoveOwnership()`, non-kinematic, velocity = `CarryRules.ClampThrow`.
  - Heavy item: the server moves the kinematic rigidbody each FixedUpdate toward the average of the holders' HoldPoints, at a speed of run speed × `SpeedFactor`. With 1 holder it drags along the floor (y locked) and raises a noise every 0.5 s.
  - Server collision while not held → `NoiseBus.Raise(FromImpact)`.
  - On a holder's disconnect → release.
  - Logs: `ITEM_GRABBED item=<id> by=<n> holders=<k>`, `ITEM_RELEASED item=<id> by=<n> reason=<throw|drop|disconnect>`, `HEAVY_LIFTED item=<id>` when it reaches 2 holders.
- `PlayerHands : NetworkBehaviour`:
  - Owner: E raycasts 2.2 m for a `GrabbableItem` → `[Rpc(SendTo.Server)] GrabRpc(NetworkObjectReference)`; LMB → `ThrowRpc(dir)`; G → `DropRpc()`.
  - Holds `NetworkVariable<NetworkObjectReference> Held` (server write) and sets `PlayerMotor.Load`.
- `PlayerPush : NetworkBehaviour`: owner RMB raycasts 2.5 m for a player → `[Rpc(SendTo.Server)] PushRpc(NetworkObjectReference target)` → server `PushRules.Evaluate` (positions from server copies) → `target.KnockbackRpc`. Logs `PUSH by=<a> target=<b> knockdown=<bool>` or `PUSH_DENIED reason=<r>`.
- `SessionFlow` (on Services):
  - On `ConnectionService` Hosting → server `NetworkManager.SceneManager.LoadScene("Sandbox", Single)`.
  - When Status becomes Offline while not in Menu → `SceneManager.LoadScene("Menu")`.
  - Bootstrap `Start` loads `Menu`.
- `SandboxBuilder.Build()` creates `Assets/_Project/Scenes/Sandbox.unity`:
  - Floor 30×30, 4 walls, a ramp, a 0.6 m step to jump
  - 4 `SpawnPoint`s
  - 4 light boxes (in-scene NetworkObjects, ids `box1..4`) and 1 heavy urn (`urn`, mass 60)
  - A dim directional moonlight and 2 point lights

### Task 5: SmokeProbe + player-smoke.ps1
**Files:** `Game/Dev/SmokeProbe.cs`, `tools/unity/player-smoke.ps1`
- Probe scripts, keyed by `-smokeprobe <role>` (only active with that flag):
  - Role `host` (server): logs `PLAYER_MOVED id=<n> dist=<m>` when a remote player has moved > 2 m from its first placed position.
  - Role `walker`: walks forward 2 s, then grabs the nearest light box, then throws it after 1 s.
  - Role `lifter`: walks to the urn and grabs it.
  - Role `holder`: grabs the nearest box and keeps it, so the script can kill this instance.
- The script (Local mode) runs:
  1. host `-autohost-local -smokeprobe host`
  2. client A `-smokeprobe walker`
  3. wait for `PLAYER_PLACED` on both, then on the host `PLAYER_MOVED id=1`, `ITEM_GRABBED`, `ITEM_RELEASED ... reason=throw`, `NOISE`
  4. clients B and C `-smokeprobe lifter` → host `HEAVY_LIFTED`
  5. client D `-smokeprobe holder` → host `ITEM_GRABBED by=<D>` → kill D → host `ITEM_RELEASED ... reason=disconnect`
