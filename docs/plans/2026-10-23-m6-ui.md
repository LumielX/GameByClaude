# M6: First UI (UI Toolkit) + Thai/English Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the IMGUI debug menus with the approved UI (the mockup at `docs/ui_mockup/`, Kanit font). Screens:
- Title, How to play, Settings
- Play (name, Create / Join / Solo), Create Room
- Lobby: 8 slots, Ready, kick, chat
- In-night HUD and Vote overlay
- Night summary / game-over ranking
- Pause and the error popup

Every text switches between Thai and English at runtime. A player can go from the title screen to the end of a game with the mouse only.

**Architecture:**
- Strings live in two plain-text tables, `Resources/Lang/th.txt` and `en.txt`, in `key=value` lines (easy for the owner to edit). Core `Localizer` parses and serves them; the TDD test checks both tables have the same keys.
- The UI assembly (`BooTrayal.UI`) holds one `UIRoot` (UIDocument on the persistent Services object) and one small controller per screen. Screens are UXML files plus one shared theme USS.
- Text elements whose UXML text starts with `@` are localized automatically by key. They are re-applied when the language changes.
- Game state stays in Game:
  - `ConnectionService`: room code, status, errors, host config
  - `NightDirector`: phase, timer, tasks, roles, meetings, summaries
  - new `PlayerLobby`: ready, chat
  - new `GameSettings`: volume, sensitivity, language, reduced effects; saved in PlayerPrefs
- The UI only reads that state and calls it.
- NightDirector's summary, meeting-result and game-over RPCs carry data (ids, numbers, enums), not Thai sentences, so each client renders them in its own language.

**Tech Stack:**
- UI Toolkit (UXML/USS, `PanelSettings` built by code)
- `style.unityTextGenerator = TextGeneratorType.Advanced` for Thai mark stacking
- `FontDefinition.FromFont(Kanit TTF)`
- Kanit (SIL OFL 1.1) from the official google/fonts repository, recorded in `CREDITS.md`

**Spec:** `docs/GDD.md` §11 (UI list, theme), §4.1 (room options), §7.4; `docs/PLAN.md` M6; approved mockup `docs/ui_mockup/project/*.dc.html` (user chose Kanit, 2026-10-23).

## Global Constraints
- All earlier constraints still apply.
- Assets: only Kanit TTFs (Regular, SemiBold, ExtraBold) plus `OFL.txt`, from `https://github.com/google/fonts/tree/main/ofl/kanit`, recorded in `CREDITS.md`.
- Theme tokens from the mockup:
  - ground `#0E0A16`, card `#1B1428`, border `#3A2E52`
  - text `#F2EEF8`, muted `#B9B0CC`, faint `#8E85A3`
  - neon `#39FF88`, purple `#7B3FE4`, warn `#FFC24B`, danger `#FF8A9B`
  - radius 14, buttons ≥ 44 px high
- Thai is the default language; English via the toggle on the title screen and in Settings. Both tables contain the same keys.
- Lobby: a game starts only when every connected player is Ready (`LobbyRules.CanStart`). Solo is 1 player. `-autostart` skips the check (smoke tests).
- Chat:
  - The server sanitizes every message (`ChatRules.Sanitize`: trim, drop control/format chars, ≤ 120 chars, empty → dropped).
  - At most 1 message per second per player.
  - The last 30 messages are kept per peer.
- Kick: the host only, in the Lobby phase. The kicked client sees a localized "you were removed" message.
- Create Room settings:
  - max players 2–8
  - Spy off / 1 / 2: the choice is shown even at 2–4 players; the effective count follows `RoomRules.SpyCount`
  - night length 8/10/12/15 min, nights 1/3/5, difficulty (stored only; no effect until M10)
  - They go into `ConnectionService.HostConfig` (GameConfig), which NightDirector uses. Launch args still override.
- Settings:
  - master volume (`AudioListener.volume`)
  - mouse sensitivity 0.03–0.4
  - language
  - "reduce visual effects": FearDirector drops shake and chromatic and halves the vignette
  - mic: a disabled row, "Vivox in M7"
- Remove `DebugNetMenu` and `NightHud` (IMGUI).
- "Open every page without exception" is checked by `-uismoke` in the built player: UIRoot visits every screen and overlay in both languages, logs `UI_SCREEN name=X lang=Y`, then `UI_SMOKE_OK`. tools/unity/ui-smoke.ps1 checks the markers and that there are no exceptions.

## Review Focus
1. **Language switch while a dynamic text is shown** (timer, lobby names, summary): it re-renders in the new language within a frame. → controllers rebuild dynamic text in `Refresh()`, which runs every frame or on Changed; ui-smoke switches language on every screen.
2. **A chat message that is huge or empty, or has control or RTL-override characters:** dropped or trimmed server-side. → `ChatRules` tests.
3. **The host leaves, or a client gets kicked or version-rejected while on any screen:** the UI returns to Title or Play with the localized error popup, not a dead HUD. → UIRoot shows Play + error popup on `NetStatus.Offline` with a `LastMessageKey`.
4. **Cursor:** free on every menu, locked only in the HUD while playing (not during vote, pause or summary). → UIRoot is the only owner of `PlayerInputReader.SetCursorFree` (the HUD vote code is removed).
5. **Thai rendering:** tone marks stack correctly and nothing renders as tofu boxes. → Advanced text generator + Kanit on the root; checked by eye in the editor screenshot step, and the PROGRESS manual check list.
